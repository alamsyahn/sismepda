# Hermes workflow for SISMEPDA

`docs/README.md` is the canonical system map. Existing behavior and durable project knowledge belong in `docs/`; Git history, not documentation, records past work.

For every task:
1. Read this file, then use `docs/README.md` to find and read **all relevant canonical documents** and related active technical debt.
2. Read only the source, tests, schema, and configuration directly needed for the task. Do not rediscover the whole architecture.
3. Implement the scoped change and run the relevant tests; for a complete verification use `npm test`, `npm run lint`, and `npm run build` (`pnpm` equivalents are acceptable when available).
4. Re-read the affected canonical docs, review links and technical debt, and update existing docs whenever behavior, rules, permissions, data, APIs, integration, architecture, or operations changed. If no durable knowledge changed, explicitly confirm the docs remain accurate.

Do **not** perform a repository-wide audit, full architecture/dependency/database inspection, or broad source scan unless the user explicitly requests a full-system inspection. Unexpected errors remain localized: use the docs, direct dependencies, logs, configuration, and data in scope; report when a separate full inspection may be needed instead of starting one.

Update existing canonical documents by default. Create a new document only for a genuinely new durable feature, subsystem, operational procedure, or architectural concern. Remove superseded duplicates after migrating valid facts. Record only verified, unresolved engineering liabilities in `docs/technical-debt/README.md`; remove an entry once its exit criteria are verified. Never turn docs into task reports, change logs, implementation diaries, or wishlists.
