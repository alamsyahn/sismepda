# Teachers and homerooms

Teacher-account administration lives at `/guru`; creation/import lives at `/guru/input`, and `/guru/kelola` redirects to `/guru`. A teacher login requires at least email or NIP, both unique where present. `teachers.accounts.*` permissions govern teacher listing, creation and identity fields; password reset, active state and permanent deletion require the separate `accounts.credentials.manage`, `accounts.status.manage` and `accounts.delete` permissions. The UI hides each control independently.

Permanent deletion has one entrypoint, `DELETE /api/rbac/accounts/[userId]`. It requires identifier confirmation, rejects self-deletion and privileged targets for non-system administrators, and runs under the system-admin population lock. Attendance attribution is reassigned to the acting administrator. Existing `StudentViolationPoint.recordedById` provenance blocks deletion with an actionable 409 response rather than being reassigned or failing as an opaque foreign-key error.

Users with `teachers.directory.read` can browse `/guru/direktori` and `/guru/[teacherId]`, including photo, employment details, subjects, duties and teaching assignments. Employment metadata, subjects, schedules and duties require their explicit `teachers.*` permissions. Schedule entries bind teacher, class, subject, weekday and inclusive period range; reversed ranges and overlapping schedules for the same teacher/day are rejected. The system does not model bell times, rooms, class-side conflict detection, substitutions, or live “currently teaching” behavior.

A user with `homerooms.assign` maps at most one homeroom teacher to each class at `/wali-kelas/input`; a user can be homeroom of at most one class because both sides are unique. This assignment defines assigned-class scope for attendance, student profiles, violation points and exports. See [Authorization](../architecture/authentication-authorization.md).

Teacher photos are database bytes and viewable to authenticated users. Teacher details also connect to [Workbook supervision](workbook-supervision.md). Primary files: `app/api/admin/teachers`, `app/api/admin/homerooms`, `app/api/teachers/**`, `lib/server-teacher-profile.ts`, and `lib/teacher-access.ts`.
