# Teachers and homerooms

Teacher-account administration lives at `/guru`; creation/import lives at `/guru/input`, and `/guru/kelola` redirects to `/guru`. A teacher login requires at least email or NIP, both unique where present. `teachers.accounts.*` permissions govern teacher listing, creation and identity fields; password reset, active state and permanent deletion require the separate `accounts.credentials.manage`, `accounts.status.manage` and `accounts.delete` permissions. The UI hides each control independently.

Permanent deletion has one entrypoint, `DELETE /api/rbac/accounts/[userId]`. It requires identifier confirmation, rejects self-deletion and privileged targets for non-system administrators, and runs under the system-admin population lock. Attendance attribution is reassigned to the acting administrator. Existing `StudentViolationPoint.recordedById` provenance blocks deletion with an actionable 409 response rather than being reassigned or failing as an opaque foreign-key error.

The **Edit** action on `/guru` opens one dialog (`components/guru/teacher-edit-dialog.tsx`) that is the primary place to manage a teacher's master profile: photo, salutation, full name, NIP, email, phone, belajar.id account, employment status, position, teaching-since date and taught subjects. It writes through three existing endpoints rather than a new one — identity to `PATCH /api/admin/teachers` (`teachers.accounts.update`, plus `accounts.credentials.manage` for email), employment to `PATCH /api/teachers/[teacherId]` (`teachers.profile.update`), photo to `PUT`/`DELETE /api/teachers/[teacherId]/photo` (`teachers.profile.update`) — so each group keeps the permission that already governed it. `lib/teacher-schemas.ts` holds one `.strict()` Zod contract shared by create and update, so a field that can be set at creation can also be corrected afterwards and a forged payload carrying `role`, `active`, `passwordHash` or any `photo*` column is rejected with 400 instead of being silently stripped. Role, permissions, active state and deletion stay outside this dialog, in account/RBAC administration.

Salutation has no column of its own: it is a free-text prefix inside `User.name`, split and recomposed by `splitPrefixedName`/`previewName` in `lib/guru-input.ts` and edited with the same `PrefixCombobox` (preset list plus custom value) used by teacher creation. Existing names without a recognised prefix stay intact.

Users with `teachers.directory.read` can browse `/guru/direktori` and `/guru/[teacherId]`, including photo, employment details, subjects, duties and teaching assignments. Employment metadata, subjects, schedules and duties require their explicit `teachers.*` permissions. Schedule entries bind teacher, class, subject, weekday and inclusive period range; reversed ranges and overlapping schedules for the same teacher/day are rejected. The system does not model bell times, rooms, class-side conflict detection, substitutions, or live “currently teaching” behavior.

A user with `homerooms.assign` maps at most one homeroom teacher to each class at `/wali-kelas/input`; a user can be homeroom of at most one class because both sides are unique. This assignment defines assigned-class scope for attendance, student profiles, violation points and exports. See [Authorization](../architecture/authentication-authorization.md).

Teacher photo bytes go through the canonical media storage layer (`storeMedia`), never into a new byte column; the legacy `photoData` bytea is read as a fallback and cleared only for rows that have just moved. Replacing or removing a photo clears the database reference and leaves file cleanup to the separate media-retirement phase, matching profile photos. Administrator uploads are bounded by the `teachers.master.photo` upload slot; see [Uploads](../architecture/uploads.md) and [Media storage](../architecture/media-storage.md). Photos are viewable to users with `teachers.directory.read`. Teacher details also connect to [Workbook supervision](workbook-supervision.md). Primary files: `app/api/admin/teachers`, `app/api/admin/homerooms`, `app/api/teachers/**`, `lib/server-teacher-profile.ts`, and `lib/teacher-access.ts`.
